# 在室カレンダー

部屋に誰がいつ居るかを、みんなで共有するためのシンプルなWebアプリです。
3〜4人程度の小さな部屋での利用を想定しています。LAN内の1台でサーバーを起動すれば、全員がブラウザから同じカレンダーを見て編集できます。

## 主な機能

- 月・週・日の表示切り替え（Googleカレンダー風。初期表示は月）
- 人ごとにアイコン画像と色を登録し、予定にアイコンを表示
- 上部の人アイコンをクリックすると、その人の予定を表示／非表示
- 同じ時間帯を複数の日にまとめて登録
  - 小さなカレンダーで日付をタップして選択
  - 曜日をタップすると、その月の同じ曜日をまとめて選択
  - PCの月表示では、日付をドラッグして範囲選択
- メモ（終日または時間指定）
  - 人に関連付け（例:「出張」「休み」）: その人の色の薄い版で表示
  - 部屋に関連付け（例:「大掃除」「ゼミ」）: グレーで表示
  - 終日で続けて選んだ日は、1本の期間メモになります
  - 時間指定は開始日時〜終了日時で登録（日をまたいでも1件）。繰り返し（毎日・平日・毎週・隔週・毎月）も選べます
  - 上部の「部屋」チップで、部屋のメモを表示／非表示
- 週・日表示では、予定をドラッグして時間を移動、端を引っ張って長さを変更
- 元に戻す: 追加・変更・移動・削除のあとに出る「元に戻す」、右上の戻るボタン、または Ctrl+Z（Mac は ⌘+Z）で、直前の操作から順に取り消せます
  - 自分の人の名前・色・アイコンの変更も元に戻せます（退会は元に戻せません）
  - 戻せるのは自分の端末でした操作だけで、最大30件まで。ページを再読み込みすると履歴は消えます
- アカウント: メールアドレスとパスワードでログインします。ログインすると、自分の予定とメモだけ編集できます（他の人のものは見るだけ）。部屋のメモは、ログインしていれば誰でも編集できます
  - 登録: 登録の画面で申し込むと、メールに6桁のコードが届きます。そのコードだけを入力して完了します（申し込んだブラウザで入力してください）。登録のとき、まだ誰も使っていない既存の人を選んで予定とメモを引き継ぐか、新しい人を作ります
  - パスワードを忘れたとき: メールに届く1回限りのリンクから、新しいパスワードを設定できます（設定すると全端末からログアウトされます）
  - 退会: 自分の人の編集画面から。人・予定・メモ・アカウントがすべて消え、元に戻せません
  - ログインしていなくても、合言葉を通れば閲覧できます（編集はできません）
- 反応（スタンプ・コメント）: ログインしていると、他の人の予定やメモにスタンプ（いいね・おこ・かなしい・ありがとう・おつかれ・わらい）と、40字までのコメントを付けられます。予定やメモを押すと出る「反応」欄から付けます
  - 同じスタンプは1人が1つの予定に1回だけ（もう一度押すと取り消し）。コメントは1人が1つの予定に5件までで、編集はできません。自分の予定・メモには付けられません。部屋のメモには、ログインしていれば誰でも付けられます
  - 消せるのは、した本人だけです（予定・メモの持ち主でも、他の人の反応は消せません）。退会すると、自分が付けた反応も消えます
  - 月・週・日の予定に、反応の数（吹き出しのマーク）が出ます
  - 右上のベルで、自分の予定・メモに付いた反応の履歴（新しい順に50件）を見られます。未読の数がバッジに出て、開くと既読になります。行を押すと、その日に移動します
  - 自分の予定に付いた反応は、次にページを開いたとき（ログインし直したとき）と、開いている間に新しく付いたときに、予定のところに吹き出しで出て「ぽん」と鳴ります（開き直しの分は、同じ端末では1回だけ。最大5件）。音は `public/sounds/pop.wav`（約1秒の「ぽーん」。同じ名前の音声ファイルで置き換えられます。`node scripts/make-pop-sound.js` で作り直せます）を鳴らします。ベルのパネルで切れ（選択は端末に覚えます）、ブラウザの決まりで、ページを開いてから最初の操作より前の分は、最初の操作のあとに鳴ります。他の人の反応は、最長で約30秒遅れて届きます
  - スタンプの絵は、はじめから内蔵のイラストです。`public/stamps/<id>.png` に画像を置くと差し替わります（`docs/stamps.md`）
- ロック: 間違って変更しないよう、ページを開いたときは必ずロックされています。ログインしているときだけ、ヘッダーの鍵ボタンで編集できます（操作がない状態が5分続くと自動でロックに戻ります）
  - ロック中も、表示の切り替え、CSV出力、印刷は使えます。予定やメモを押すと、内容（日時・メモ）を見られます（編集はできません）
  - スマホでは、ロックとログイン以外のヘッダーのボタン（ログアウトを含む）は「…」メニューに入っています
- キーボードモード: ログイン中に `i` を押すと、キーボードだけで操作できるモードに入ります（ロックを解除し、月表示にします。操作する人は自分です）。`Esc` で終了すると、ロックに戻ります
  - 移動: `←` `→` `↑` `↓`（`h` `l` `k` `j` も可）でカーソルを動かします。月表示は日・週ごと、週・日表示は日・30分ごとです。`Shift` を押しながら動かすと範囲を選べます
  - `Home` / `End`（月: 週の頭・末、週・日: 0:00・23:30）、`PageUp` / `PageDown`（`[` `]` も可）で前後の月・週・日へ、`t` で今日へ
  - `m` / `w` / `d` で月・週・日表示を切り替え
  - `Enter` で在室を追加（月: 9:00〜18:00、週・日: カーソルの時刻から1時間。範囲を選んでいればその範囲）、`n` でメモを追加
  - `Tab` / `Shift+Tab` でその日のイベントを順に選び、`e` で編集、`x`（`Delete`）で削除。`u`（`Ctrl+Z`）で元に戻す
  - `?` でキー一覧
- 日曜・祝日は赤、土曜は青で表示（祝日名も表示）
- スマホ対応（右下の「＋」ボタンで追加、月表示で日付をタップするとその日の表示へ）

## 必要なもの

- Node.js 22.13 以降（組み込みの `node:sqlite` を使います。動作確認は Node.js 26）

## 使い方

```sh
npm install
npm start
```

起動後、ブラウザで `http://localhost:3000` を開きます。
同じLAN内の他の端末からは `http://<サーバーのIPアドレス>:3000` でアクセスできます。

1. 右上の「ログイン」から新規登録します。申し込むとメールに6桁のコードが届くので、そのコードを（申し込んだブラウザで）入力すると、ログインした状態になります。ページを開き直しても、コード入力の画面に戻れます。まだ誰も使っていない既存の人があれば選べます。新しく作る場合は、名前と色を決めます（画像は、登録後に自分の人の鉛筆から設定します）。
2. カレンダーの日付をクリックするか右下の「＋」を押して、在室時間を追加します。
3. 右下のメモボタンでメモを追加します。在室の追加画面の上にある「メモ」タブからも切り替えられます。
4. 予定やメモをクリックすると、編集・削除できます。

### 設定（環境変数）

| 変数 | 既定値 | 説明 |
| --- | --- | --- |
| `PORT` | `3000` | 待ち受けるポート番号 |
| `DATA_DIR` | `./data` | データベースと画像の保存先 |
| `PUBLIC_URL` | （自動） | 公開URL（例: `https://room.example.com`）。パスワード再設定のメールに入る URL と、共有時の画像の URL の元になります。HTTPS のプロキシの後ろでは必ず設定してください。`SMTP_HOST` を設定するときは必須で、未設定だとパスワード再設定のメールは送られません。アクセス先の `Host` ヘッダーから URL を作る代わりの動きは、`SMTP_HOST` を設定していないとき（コンソール出力）と、共有時の画像の URL だけです。`https://` で始まる値にすると、ログインの Cookie に `Secure` が付くので、`http://` のままではログインできなくなります |
| `APP_TITLE` | `在室カレンダー` | アプリの名前。左上の見出し、ブラウザのタブのタイトル、共有時のタイトル（`og:title`・`og:site_name`）、合言葉・ログイン・ログアウト確認の画面、確認コードとパスワード再設定のメールの件名・本文に使います。前後の空白は取り、改行や連なった空白は1つの空白にして、40文字までに切ります。未設定・空・空白だけのときは既定の名前です。`.env` に書いた場合も使えます。共有時の画像（`public/iruinai-ogp.png`）には既定の名前の文字が焼き込まれているので、`APP_TITLE` を変えても画像の文字は変わりません（変えたいときは画像を差し替えてください）。起動時のログの `在室カレンダー: http://localhost:PORT` も変わりません |
| `ROOM_PASSWORD` | （なし） | 部屋の合言葉。設定すると、開くときに合言葉の入力が必要になります |
| `ENV_FILE` | `./.env` | 読み込む `.env` ファイル。起動時に自動で読みます（なければ何もしません。すでに設定した環境変数は上書きしません） |
| `SMTP_HOST` | （なし） | メール送信用の SMTP サーバー。未設定のときはメールを送らず、確認コードとリセット URL をサーバーのコンソールに出します |
| `SMTP_PORT` | `587` | SMTP のポート |
| `SMTP_SECURE` | `false` | `true` にすると TLS で接続します（ポート 465 のとき） |
| `SMTP_USER` / `SMTP_PASS` | （なし） | SMTP の認証情報 |
| `MAIL_FROM` | `SMTP_USER` | 送信元。例: `在室カレンダー <noreply@example.com>` |
| `MAIL_IP_LIMIT` / `MAIL_GLOBAL_LIMIT` | `10` / `100` | メールを送る要求（登録の申し込み・コードの再送・パスワード再設定）の上限（要求の回数）。`MAIL_IP_LIMIT` は同じ IP から1時間あたり、`MAIL_GLOBAL_LIMIT` は全体で1時間あたりです。超えると `429` を返し、メールは送りません（下の「注意事項」を参照）。使えるのは1以上の10進の整数だけで、`0` は「無効」ではありません。それ以外の値（`0`・負の数・`0x10`・`1e3` など）は、起動時に警告を出して既定の値を使います。`MAIL_IP_LIMIT` が `MAIL_GLOBAL_LIMIT` 以上のときも、IP ごとの上限が働かないので、起動時に警告を出します |

例: `PORT=8080 DATA_DIR=/srv/room-calendar npm start`

`.env.example` を `.env` にコピーして書き換えると、起動のたびに環境変数を指定しなくて済みます（`.env` は Git に入りません）。

### 合言葉

`ROOM_PASSWORD=好きな合言葉 npm start` で起動すると、最初に合言葉の入力画面が出ます。

- 全員が同じ合言葉を使います（人ごとのログインではありません）
- 合言葉は「閲覧用」です。アカウントの登録やログインの画面も、合言葉を通った後に開きます
- 一度入ると、そのブラウザでは1年間入力不要です
- 合言葉の前に開いたページ（`/account`、メールのパスワード再設定のリンク `/reset?token=…` など）は、合言葉を入力したあとにそのページへ戻ります（`/login?next=…`）。戻れるのはこのサイトの中のページだけで、外部のサイトや `/login`・`/logout` を指す値は無視して `/` へ進みます
- 合言葉を変えて再起動すると、全員がもう一度入力することになります
- `/logout` は、合言葉とログインの両方をログアウトします。アドレス欄やブックマークから開いたとき、またはこのサイト（同じオリジン）のリンクから開いたときは、すぐにログアウトします。他のサイトのリンクなどから開かれたとき（`Sec-Fetch-Site` が `cross-site`・`same-site`、または付いていないとき）は、勝手にログアウトさせられないよう「ログアウトしますか？」の確認画面を出し、ボタンを押すと `POST /logout` でログアウトします
- 同じ端末から5回続けて間違えると、1分間入力できなくなります
- 通信は暗号化されません（HTTP）。インターネットに公開する場合は HTTPS の下で動かしてください

## データ

- データベース: `data/app.db`（SQLite）
- アイコン画像: `data/uploads/`

バックアップするときは `data/` フォルダごとコピーしてください。

ログイン情報（`users`, `sessions` など）も `data/app.db` に入ります。パスワードはハッシュ（scrypt）で保存され、元の文字列は残りません。

人の画像を変えても、元に戻せるように古い画像はすぐには消しません。どの人にも使われていない画像（変更前の画像や、退会した人の画像）は、次に起動したときにまとめて削除します。

起動時に、大きいままのアイコン画像を自動で 144px の WebP に縮小します（変換済みは何もしません）。縮小に使う `sharp` が入っていない環境ではスキップし、元の画像のまま動きます。

### API

`GET` は誰でも（合言葉を通れば）使えます。それ以外の `/api/*` は、ログインが必要です（`/api/auth/*` を除きます。未ログインは `401`）。他の人の在室・メモを操作すると `403` になります。

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET / POST | `/login` | 合言葉の入力（`ROOM_PASSWORD` 設定時のみ）。`next` に、合言葉のあとに戻るこのサイト内の場所を指定できる |
| GET | `/logout` | ログアウト（合言葉とログインの両方。`ROOM_PASSWORD` 設定時のみ）。`Sec-Fetch-Site` が `same-origin` か `none` のときだけ実行し、それ以外は確認画面を返す |
| POST | `/logout` | ログアウトを実行して `/login` へ（確認画面のボタンの送り先。`ROOM_PASSWORD` 設定時のみ。`Sec-Fetch-Site` が `same-origin` 以外のブラウザからの送信は実行せず、確認画面を返す） |
| GET | `/account`, `/reset` | ログイン・登録・パスワード再設定の画面（パスワード再設定のリンクは `/reset?token=…`） |
| GET | `/api/me` | ログイン中のユーザー（未ログインは `{ "user": null }`） |
| POST | `/api/auth/signup` | 登録の申し込み（`email`, `password`, `person_id` または `new_name`/`new_color`）。確認コードをメールで送り、申し込んだブラウザに Cookie `iruinai_signup`（`HttpOnly`・`SameSite=Lax`・`Path=/api/auth`・1時間）を渡す（メールの送信上限あり）。同じブラウザが同じメールをもう一度申し込んだときは、メールを送らず `{ "ok": true, "resumed": true }` を返す |
| POST | `/api/auth/verify` | 6桁コードの確認（`{ "code" }` だけ。確認待ちは Cookie `iruinai_signup` で決まり、メールやパスワードは送らない）。コードの間違いは5回までで、成功するとログインし、Cookie は消える。Cookie がない・合う確認待ちがないときは `400`（「確認の手続きが見つかりません」） |
| POST | `/api/auth/resend` | コードの再送（本文なし。確認待ちは Cookie で決まる。60秒に1回、1つの登録につき3回まで。間違いの回数は戻らない。メールの送信上限あり） |
| GET | `/api/auth/pending` | このブラウザの確認待ち。あれば `{ "pending": { "email", "expires_at", "resend_available_at", "locked" } }`（時刻は UNIX ミリ秒）、なければ（Cookie がないときも）`{ "pending": null }`。ページを開き直したときに、コード入力の画面へ戻るために使う |
| POST | `/api/auth/login` | ログイン（`email`, `password`） |
| POST | `/api/auth/logout` | ログアウト |
| POST | `/api/auth/forgot` | パスワード再設定のメールを送る（登録の有無にかかわらず同じ応答。メールの送信上限あり） |
| POST | `/api/auth/reset` | 新しいパスワードを設定（`token`, `password`） |
| POST | `/api/me/withdraw` | 退会（`password`）。人・在室・メモ・アカウントを削除。パスワードを5回続けて間違えると、そのアカウントは1分間（正しいパスワードでも）退会できません（`429`） |
| GET | `/api/people` | 人の一覧（`claimed` は、アカウントと紐付け済みなら `1`） |
| PUT | `/api/people/:id` | 人を更新（本人のみ。`removeIcon=1` で画像を外す）。画像は2MBまで（超えると `400`）。アップロードの内容が壊れているときも `400` |
| GET | `/api/stays?start=&end=` | 期間内の在室一覧 |
| POST | `/api/stays` | 在室を1件追加 |
| POST | `/api/stays/batch` | 同じ時間で複数日に追加（`person_id`, `dates`, `startTime`, `endTime`, `note`） |
| PUT | `/api/stays/:id` | 在室を更新 |
| DELETE | `/api/stays/:id` | 在室を削除 |
| GET | `/api/memos?start=&end=` | 期間内のメモ一覧 |
| POST | `/api/memos/batch` | メモを追加（`person_id`（部屋は `null`）, `title`, `all_day`, `items: [{start, end}]`） |
| PUT | `/api/memos/:id` | メモを更新 |
| DELETE | `/api/memos/:id` | メモを削除 |
| GET | `/api/reactions/summary?from=&to=` | 期間内の予定・メモごとの反応の要約（スタンプの数、自分が付けたもの、コメント数）。反応のないものは含まない |
| GET | `/api/reactions/:type/:id` | 1つの予定（`stay`）かメモ（`memo`）の反応を古い順に |
| POST | `/api/reactions` | 反応を付ける（`type`, `id` と、`stamp` または `body`）。自分の予定・メモには付けられない（`400`）。1人が1分に30回まで（追加と削除の合計。超えると `429`） |
| DELETE | `/api/reactions/:id` | 反応を消す（した本人だけ。それ以外は `403`） |
| GET | `/api/notifications` | 自分の予定・メモへの、他の人の反応（新しい順に50件）と未読数。ログインが必要 |
| POST | `/api/notifications/seen` | 既読にする |

メモの日時は、終日なら `YYYY-MM-DD`（`end` は最終日の翌日）、時間指定なら `YYYY-MM-DDTHH:MM:SS` です。

## 注意事項

- `ROOM_PASSWORD` を設定しない場合、LANにつながる人なら誰でも閲覧でき、アカウントも登録できます。
- 通信は暗号化されません（HTTP）。パスワードやメールの確認コードが平文で流れるので、インターネットに公開する場合は必ず HTTPS の下で動かしてください。
- 人は登録のときにだけ作ります。誰にも紐付けられていない既存の人は、紐付けられるまで誰も編集できません（紐付けの解除はできません）。
- リバースプロキシの後ろで動かすときは、次の点に注意してください。
  - Express の `trust proxy` は設定していないので、アクセス元の IP アドレスはプロキシのものになります。合言葉とログインの「5回続けて間違えると1分間入力できなくなる」制限と、メールを送る要求の「同じ IP から1時間に10回まで」の上限は IP ごとに数えるため、全員の分がまとめて数えられます（メールの上限は、全員で1時間に10回を分け合うことになります）。
  - 合言葉の Cookie には、`Secure` が自動では付きません。ログインの Cookie には、`PUBLIC_URL` が `https://` で始まっていれば `Secure` が付きます。
- `PUBLIC_URL` を `https://…` にすると、ログインの Cookie に `Secure` が付くため、`http://<LAN内のIPアドレス>:3000` のような HTTP のままではログインできません（Cookie が保存されません）。HTTPS でアクセスするか、LAN 内だけで使うなら `PUBLIC_URL` を設定しないでください。
- 登録の総当たり対策は、確認待ちの登録ごとに数えます（IP ごとではありません）。コードの間違いは5回まで（再送しても戻りません）、再送は3回まで、再送の間隔は60秒、コードの有効期間は10分です。IP ごとに数えるのは、合言葉とログインの失敗と、次に書くメールを送る要求の回数です。退会のパスワードの間違いは、アカウントごとに数えます（5回続けて間違えると1分間、正しいパスワードでも退会できません。成功しても回数は戻りません）。
- 登録の確認コードは、登録の申し込みを送ったブラウザでしか入力できません。申し込むと、そのブラウザに Cookie `iruinai_signup`（`HttpOnly`・`SameSite=Lax`・`Path=/api/auth`、有効期間1時間）が渡され、確認コードの画面は、その Cookie に結び付いた手続きだけを確認します（コードの有効期間は10分）。他の人が自分のパスワードであなたのメールアドレスを登録し、届いたコードをあなたに入力させて、その人がパスワードを知っているアカウントに入らせる、という乗っ取りを防ぐためです。あなたのブラウザにはその Cookie がないので、コードが合っていても確認できません。
  - 別の端末や別のブラウザに切り替えたり、Cookie を消したりした場合は、確認できません。同じメールアドレスの確認待ちは、他のブラウザからは上書きも確認もできないので、10分ほど待ってから申し込み直してください。
  - 同じブラウザで、同じメールアドレスをもう一度申し込んだ場合（戻るボタンや再読み込みなど）は、メールを送り直さずにコード入力の画面に戻ります。このとき、申し込みの内容（パスワードなど）は最初のままです。コードを送り直したいときは「コードを再送する」を使います。
- メールを送る要求（`/api/auth/signup`・`/api/auth/resend`・`/api/auth/forgot`）には、メールの送りすぎを防ぐ上限があります。同じ IP から1時間に10回、全体で1時間に100回までで（回数は要求の数です）、超えると `429`（「送信の回数が多すぎます。しばらくしてからやり直してください」）を返し、メールは送りません。
  - 数えるのは、メールを送るところまで進んだ要求だけです（入力の誤りや、登録済み・確認待ちなどで送らずに終わる要求は数えません）。`/api/auth/forgot` は、登録の有無が分からないよう、書式が正しい要求を宛先が登録済みかどうかにかかわらずすべて数え、上限を超えたら誰に対しても同じ `429` を返します。
  - IP ごとの上限は IP ごとに数えるので、1つの IP が使い切っても、別の IP は影響を受けません。全体の上限（1時間に100回）を使い切るには、複数の IP が要ります。使い切られると、その後最大1時間は、他の人の登録やパスワード再設定のメールも送られません。リバースプロキシの後ろで `trust proxy` を設定していないときは、全員が1つの IP として数えられるので、全員で1時間に10回を分け合います。上限は `MAIL_IP_LIMIT` と `MAIL_GLOBAL_LIMIT` で変えられます。数えるのはサーバーのメモリ上です（再起動すると 0 に戻ります）。
- 既存の環境をアップグレードするときは、先に `data/`（`app.db` と `uploads/`）をバックアップしてください。アップグレードすると、すでにある人はすべて「誰にも紐付けられていない人」になり、合言葉を知っている人なら誰でも、そのうちの1人を選んで登録できます。みんなで早めに登録してください。
- 他の人の変更は、ページを開き直すかタブに戻ったときに反映されます（自動更新はしません）。
- 1件の在室は1日の中で登録します。日付をまたぐ場合は日ごとに分けて登録してください。
- 祝日は現行の祝日法をもとに計算しています。法改正や特例の年には `public/holidays.js` の修正が必要です。
